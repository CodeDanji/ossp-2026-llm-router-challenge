PromptBudget v3 delta-utility 인수인계

작성일: 2026-08-26 · 대상: 다음 구현 세션/작업자 · 기준 브랜치: codex/promptbudget-v3

현재 판정: screening No-Go. v3는 공개 Dev 880에서 bundled v2.1보다 최종 가중 점수가 0.050767 낮았다. 이는 정식 Train Go/No-Go가 아니라, 정식 nested-CV에 추가 계산비용을 쓰지 말아야 한다는 비구속적 중단 신호다. 현재 구현은 연구용 부분 구현이며 v3 설계서의 정식 평가 요구를 충족하지 않는다.

0. 다음 대화에서 바로 시작하는 법

첫 번째로 이 HTML을 읽고, 다음 설계서를 이어서 읽는다.

docs/superpowers/specs/2026-08-26-promptbudget-v3-nested-evaluation-design.md

현재 승인된 방향은 “v3 성능 개선”이 아니라 Train nested evaluation 정정이다. 상세 구현 계획은 아직 작성 전이므로, 다음 작업자는 설계서 검토 승인 여부를 먼저 확인한 뒤에만 plan을 작성한다. full 3×5 evaluation, Dev 재보정, final artifact refit, 기본 artifact 변경, merge/push는 실행하지 않는다.

새 대화에 아래 문장을 그대로 붙여 넣으면 충분하다.

PromptBudget v3 작업을 재개한다. 먼저 docs/skt/2026-08-26-promptbudget-v3-screening-handoff.html 및 docs/superpowers/specs/2026-08-26-promptbudget-v3-nested-evaluation-design.md를 읽고, 설계서의 범위 안에서 상세 구현 계획만 작성해 줘. 구현이나 full nested-CV 실행은 하지 마.

1. 다음 세션의 즉시 지시

  1. 지금 상태로 full nested-CV를 실행하지 않는다. Dev screening이 명백히 부정적이고, trainer 자체도 설계서의 nested 정책 평가를 아직 구현하지 않았다.
  2. 사용자가 v3 연구 재개를 명시적으로 승인하면, 먼저 아래 “정식 설계와의 차이”를 줄이는 작은 설계/구현 작업을 한다. 그 뒤에만 Train outer 평가를 실행한다.
  3. 기본 배포 artifact src/promptbudget/resources/artifact.json와 manifest는 절대 바꾸지 않는다. v3는 계속 build/promptbudget-v3/ 아래의 research artifact여야 한다.
  4. 사용자가 단순히 제출 성능을 원한다면 v2.1을 유지한다. 현재 evidence에서는 v3를 v2.1 대체 후보로 승격할 근거가 없다.

2. 대회와 프로젝트 맥락

이 작업은 SKT OSSP 2026 LLM Router Challenge의 PromptBudget 라우터 연구다. runtime은 prompt와 tier만으로 모델 ID 하나를 결정해야 하며, 실제 outcome·비용·ID·split·순서·네트워크를 사용할 수 없다. 공개 Train/Dev의 score/token/cost는 학습·검증에만 쓴다. tier 예산은 선택된 실제 비용으로 판정된다.

단계핵심 흐름과 관찰
v1all-Light 안전 baseline. 비용은 안전하지만 upgrade 품질 기회를 쓰지 못함.
v2모델별 absolute quality를 예측해 차감. 상대 이득과 비용 위험을 과대평가하는 문제가 관찰됨.
v2.1OOF monetary cost calibration과 공개 Dev policy calibration을 추가. 기본 shipped artifact는 absolute-linear v2.1이며 Dev weighted score는 0.670085227273.
v3 설계Light 기준 delta_quality, p_win, incremental_relative_cost를 별도 head로 학습하고, Train grouped nested-CV를 통과한 경우에만 Dev calibration으로 가는 research-only 후보를 정의.
이번 세션v3 schema/runtime/train skeleton을 추가하고 실제 Train artifact와 Dev 880 screening을 실행. v3가 거의 all-Light로 붕괴해 v2.1보다 낮은 점수를 냄.

3. 합의된 의도와 의사결정

  • 사용자 요청: 서브에이전트는 보수적으로 활용하고, 테스트를 과도하게 늘리지 않는다.
  • v3는 배포 승격이 아닌 research-only delta-linear artifact다. v1/v2 loader 및 기본 resources의 호환성은 유지한다.
  • 공개 Dev 880은 “실제 결과를 보는 screening”에는 쓰되, formal Go/No-Go의 근거로 쓰지 않는다.
  • 합의한 순서: Windows 출력 문제 해결 → Dev v3 점수 확인 → 같은 조건의 v2.1/v3 비교 → 결과가 유망할 때만 full nested-CV 투자.
  • screening이 부정적이므로 마지막 조건은 충족되지 않았다. full nested-CV는 의도적으로 미실행이다.

5. Windows 출력 문제: 원인과 수정

두 가지가 섞여 있었다.

  1. 실제 코드 결함, 수정 완료: README에 제시된 PYTHONPATH=src python -m promptbudget.runtime …는 module import만 하고 main()을 실행하지 않았다. src/promptbudget/runtime.py에 if __name__ == "__main__": raise SystemExit(main())를 추가했고, --help subprocess 회귀 테스트를 추가했다.
  2. 로컬 Windows 환경 특성: worktree의 build/promptbudget-v3 경로가 ReadOnly 속성을 상속해 output 생성에 부적합했다. screening output은 existing writable parent인 C:\tmp\promptbudget-v3-dev-screening에 썼다. runtime의 “output parent는 사전에 존재해야 한다” 계약은 바꾸지 않았다.

7. 정식 v3 설계와의 결정적 차이

이 항목들이 해결되기 전에는 v3 artifact를 평가 후보 또는 shipped artifact로 취급하지 않는다.
  1. 진짜 outer policy evaluation 부재: 현재 outer loop는 각 outer-train의 head spec 선택 이력만 기록한다. 선택된 policy를 outer-test에 적용해 actual cost/score/upgrade 결과를 측정하지 않는다.
  2. 비용 calibration 누수: final residual offset은 cross-fit residual이 아니라 in-sample prediction residual 기반이다. v3 설계가 요구한 0.90/0.95/0.99 quantile 선택도 구현되지 않았고 0.95가 고정돼 있다.
  3. inner selection의 근사: 비용 때문에 inner selection은 dense-only ridge surrogate를 사용한다. sparse-feature grid 의미가 바뀌며, win-probability selection도 model별 target이 아닌 제한된 target을 이용한다.
  4. 정식 지표/판정 부재: required signal table, 비용 coverage/slack, tier policy comparison, content-group bootstrap CI, v2.1 대비 actual-cost admission이 없다. 따라서 report의 go_no_go는 evidence 기반 결론이 아니다.
  5. 관측된 정책 붕괴: 0.95 residual offset이 큰 값으로 형성되어 cost gate가 upgrade를 막는다. 이것은 수정 전 반드시 진단해야 할 모델/보정 문제이며, 단순 tier knob 완화로 우회하면 안전 주장만 약화된다.

C:\Users\alvin\바탕 화면\창프\오픈소스\router-repo\.worktrees\promptbudget-v3

NumPy가 있는 bundled Python:

C:\Users\alvin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe

데이터 materialization용 .venv-data는 현재 NumPy 없는 runtime을 가리키므로 train/test에 쓰지 않는다. materialization만 다음으로 이미 완료했다.

.venv-data\Scripts\python.exe tools\materialize_public_data.py --split train --split dev

현재 artifact 재생성 명령(참고용; 결과가 negative이므로 반복 실행 권장하지 않음):

$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$py = 'C:\Users\alvin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $py tools\train_delta.py --input data\materialized\train\inputs.json --outcomes data\train\outcomes.json --artifact build\promptbudget-v3\artifact.json --manifest build\promptbudget-v3\manifest.json --report build\promptbudget-v3\train-nested-cv.json --max-sparse-features 16

Dev output 및 score 재현에는 existing writable parent를 쓴다. runtime tier 값은 반드시 lowercase다.

$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$py = 'C:\Users\alvin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$out = 'C:\tmp\promptbudget-v3-dev-screening'
New-Item -ItemType Directory -Force -Path "$out\v3", "$out\v21" | Out-Null
foreach ($tier in 'fast','balanced','premium') {
  & $py -m promptbudget.runtime --artifact build\promptbudget-v3\artifact.json --manifest build\promptbudget-v3\manifest.json --input data\materialized\dev\inputs.json --tier $tier --output "$out\v3\$tier.json"
  & $py -m promptbudget.runtime --input data\materialized\dev\inputs.json --tier $tier --output "$out\v21\$tier.json"
}
& $py -m ossp_router.cli self-check --input data\materialized\dev\inputs.json --outcomes data\dev\outcomes.json --submissions "$out\v3" --report "$out\v3-score.json"
& $py -m ossp_router.cli self-check --input data\materialized\dev\inputs.json --outcomes data\dev\outcomes.json --submissions "$out\v21" --report "$out\v21-score.json"
