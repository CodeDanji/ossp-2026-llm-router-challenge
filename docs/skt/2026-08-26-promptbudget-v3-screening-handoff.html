PromptBudget v3.3 완료 · v4 연구 인수인계

갱신일: 2026-08-27 · 이 문서는 다음 대화가 이전 실험을 재실행·재해석·혼합하지 않도록 만드는 단일 시작점이다.

현재 상태: v3.3은 비용 안전성 검증을 통과한 frozen baseline이다. v3.3은 Train-only grouped nested evaluation에서 45/45 actual budget check, fallback 0, non-Light retention 80.62%를 달성했고 finalization 및 단 한 번의 Dev sanity까지 끝냈다. 그러나 이는 점수 개선 완료가 아니라 “비용을 안전하게 다루는 기준선 확보”다. 다음 연구(v4)의 일은 이 기준선을 다시 튜닝하는 것이 아니라, 보수적 guard가 낳은 품질 손실을 Train 데이터에서 설명하고 단 하나의 개선 가설을 검증하는 것이다.

2. 연구의 큰 목표와 현재 목표

큰 목표: strict tier budget 안에서 all-Light보다 높은 품질을 내는 prompt-only router를 만든다. 즉 “예산을 간신히 통과하는 route”가 아니라, hidden 입력에서도 비용 초과 위험을 관리하면서 품질을 올릴 수 있는 route를 찾는 일이다.

v3.3의 목표: 비용 예측의 underprediction tail이 base predicted cost 위치에 따라 다른지 확인하고, 4개 bucket의 p90 nonnegative guard로 실제 예산 안전성을 얻을 수 있는지 시험했다. quality model, allocator, feature family를 찾는 실험이 아니었다.

v4의 현재 결론: frozen v3.3을 비교 기준으로 한 Train-only deadline triage에서 guard 아래 AX31 fill은 품질을 회복하지 못했다. 남은 개선 가설은 budget allocation이 아니라 quality ranking / upgrade 가치 추정이다. 다음 대화에서는 구현 전에 기존 hash-regex head의 AX31−Light predicted uplift가 held-out actual uplift를 순위화하는지 진단하고, 별도로 v3.3 제출 경로를 점검한다.

5. 반복하면 안 되는 실수와 작업 규율

  • 실험 family를 섞지 않는다. delta-linear v3 No-Go와 hash-regex v3.2/v3.3 결과는 서로 다른 가설이다. 한 family의 실패를 다른 family의 성능 결론으로 쓰지 않는다.
  • 공정한 comparator를 쓴다. Train outer-test에서는 published all-Train artifact가 아니라 같은 outer-train으로 다시 fit한 baseline과 비교한다. outer-test는 선택·threshold·feature 변경에 재사용하지 않는다.
  • 예측 비용으로 pass를 선언하지 않는다. admission·promotion은 공식 scorer의 actual cost로 한다. pooled average, 반올림값, predicted ratio가 45개의 actual check를 대체할 수 없다.
  • complete runtime policy를 평가한다. batch Lagrange allocator, 결정적 tie-break, Premium AX31 fill까지 적용한 최종 route를 채점한다. Premium fill을 빼면 안전성 결과가 무효다.
  • Dev를 재튜닝 루프로 쓰지 않는다. 과제 규칙상 공개 Dev 정책 보정은 허용되었던 역사와, v3.3/v4 연구의 one-pass Dev sanity 규칙을 혼동하지 않는다. 이 연구 track에서는 Train-only로 후보를 고르고 Dev는 동결 artifact에 한 번만 쓴다.
  • v3.3을 다시 돌리지 않는다. full nested run과 Dev sanity는 이미 완료됐다. guard quantile, bucket 수, retention 기준, threshold를 Dev 결과로 다시 탐색하지 않는다.
  • 기본 runtime/artifact를 덮어쓰지 않는다. 연구 산출물은 build/hash-regex-tail-guard/ 또는 새 v4의 격리 build 경로에만 쓴다. 실패 후보는 public v1 fallback을 대체하지 않는다.
  • runtime 규칙을 지킨다. prompt+tier 외 ID/split/order/실제 outcome·비용/네트워크를 쓰지 않고, ID·순서 permutation invariance와 parser/runtime 경계를 유지한다.
  • 오래된 계획을 자동 실행하지 않는다. hash-regex-quality-objective 문서는 이전 가설의 근거일 뿐 현재 승인된 v4 plan이 아니다. v4 원인 분석과 새 decision record 없이 그 Task를 재개하지 않는다.

무효 report 주의: 첫 screening.json은 obsolete model ID 결함 때문에 recoverable pool을 0으로 계산했으며 판단 근거가 아니다. 수정 뒤의 screening-corrected.json만 유효하다. 이 재실행은 threshold/seed/candidate 변경이 아닌 P0 결함 수정 뒤의 첫 유효 실행이다.

다음 대화의 승인된 범위는 논의와 진단 설계다. 새 feature, guard, threshold, artifact를 구현하거나 Train full nested/Dev를 실행하지 않는다.

  1. 개선 진단 논의: fixed grouped 4-fold held-out Train에서 guard-admissible Light 행의 AX31−Light predicted uplift 분위수별 observed uplift를 비교한다. 상위 구간의 positive lift가 없으면 ranking 기반 개선도 중단한다. 이는 이전 delta-linear No-Go를 재개하는 지시가 아니다.
  2. 제출 점검 논의: v3.3 final artifact hash·manifest·parser/runtime·complete Premium fill 경로와 제출 bundle을 확인할 최소 check를 설계한다. 이미 실행한 Dev sanity를 재실행하거나 Dev score로 tuning하지 않는다.
  3. 새 가설은 사전등록 후에만: comparator, Train-only split, actual-cap gate, materiality gate (mean cap-neutral delta ≥ +0.005), fallback, Dev one-pass 조건을 문서로 승인받은 뒤에만 구현한다.
