PromptBudget v3.3 완료 · v4 연구 인수인계

갱신일: 2026-08-27 · 다음 대화의 목적: 점수 개선 가설을 설계하고 Train-only evidence로 검증하기

v3.3은 고정 baseline으로 확정됐다. Train-only nested evaluation은 45/45 actual budget check를 통과했고 fallback은 0회였다. full-Train finalization과 단 한 번의 Dev sanity도 완료했다. 다음 작업은 v3.3을 재튜닝하는 일이 아니라, 이를 비교 기준으로 한 별도 v4 연구다.

1. 목적과 목표

목적: v3.3의 request-level tail-aware cost guard가 보장한 비용 안전성을 보존하면서, 낮은 Dev 공식 점수의 원인을 Train 데이터에서 분석한다.

v4 목표: frozen v3.3 artifact를 baseline으로 두고, 하나의 quality/routing 개선 가설을 사전등록한다. 그 가설은 Train-only grouped nested evaluation에서 안전성(모든 tier actual cap pass, fallback 없음)을 유지하며 공식 routing score를 v3.3 기준보다 의미 있게 높여야 한다. Train 결과가 이 조건을 만족하는 경우에만 새 artifact를 고정하고 Dev sanity를 한 번 실행한다.

3. 고정 baseline과 금지사항

  • 고정: ossp-hash-regex-tail-guard-v1 artifact, 4 bucket, p90 residual guard, seed 137 finalization, Raw cost head, batch Lagrange allocator, Premium AX31 fill, tier safety ratio 1.0.
  • 금지: v3.3 full run/Dev sanity 재실행, Dev 결과를 보고 threshold·guard·route를 조정하는 행위, bucket 수·quantile·retention 기준을 사후 탐색하는 행위.
  • fallback: 새 후보가 Train gate 또는 Dev sanity를 통과하지 못하면 baselines/hash-regex-public.v1.json을 사용한다.
  • 해석 경계: Dev 점수 0.67295는 제출/운영 후보의 sanity evidence이지, hidden generalization 또는 quality 개선의 증명은 아니다.

4. 다음 대화에서 할 일

  1. Train-only counterfactual 분석으로 score 손실을 tier·모델·prompt group별로 분해한다.
  2. 다음 중 하나의 원인을 선택한다: quality head의 ranking 오류, AX31/Think uplift 추정 오류, 또는 allocator가 guard 비용 아래에서 남긴 budget의 비효율적 사용.
  3. 선택한 원인에 대한 단 하나의 v4 가설, 비교군, Train-only gate를 decision record와 implementation plan에 고정한다.
  4. 가설 구현 후 focused test → one-fold smoke → 정확히 한 번의 Train full nested evaluation 순서로 실행한다.
  5. 안전·점수 gate를 통과한 후보만 finalization 후 Dev sanity를 한 번 실행한다.
